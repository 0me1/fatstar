# UI: спецификация по предоставленным референсам

Статус: изучены все три скриншота пользователя: «Мои цели», поиск для завтрака и дневник. Размер полученных изображений 945×2048, исходный 1080×2340. Плотность Android неизвестна: ниже задаются собственные logical pixels, а не утверждается точное восстановление размеров исходного приложения. Ресурсы и иконки собственные/лицензированные; графика YAZIO не копируется.

## Разбор референсов и принятые решения

- Дневник: верхняя графитовая панель с крупным «Сегодня» и календарем; ниже заголовок «Сводка», широкая карточка с открытым снизу кольцом, остатком в центре, потреблением слева и тремя полосами БЖУ внизу. Затем заголовок «Питание» и единая карточка приемов с разделителями, круглыми значками слева и круглыми кнопками + справа.
- Добавление: крупный заголовок приема, поле поиска с бирюзовой обводкой, фильтры и список строк. Название/бренд/порция слева, ккал и контурный + справа; между строками тонкий divider. Внизу счетчик выбора и широкая кнопка «Готово» над списком.
- Цели: центрированный заголовок с возвратом, одна скругленная карточка. Каждая строка содержит белую подпись слева, бирюзовое значение справа и chevron. Длинные значения и подписи занимают две строки.
- Заимствуются композиция и визуальная иерархия. Бриллианты, серии дней, «Сожжено», камера, сканер, голосовой ввод, рецепты, Pro и шаги отсутствуют: соответствующих сценариев в ТЗ нет. Значения продуктов и целей из скриншотов не являются стартовыми данными.
- Вместо ряда неподдерживаемых способов ввода предусмотрены работающие действия «Создать продукт» и «Быстрые КБЖУ». Навигация соответствует четырем разделам собственного приложения.

## Геометрия ключевых элементов

Базовый макет 393 logical pixels по ширине, с адаптацией для 360–600. Общие поля 16; ширина карточки равна доступной ширине минус 32. Высоты задаются минимумами и растут с текстом.

| Элемент | Размер / поведение |
|---|---|
| Панель дневника | safe area + минимум 64; заголовок 28–30, календарь и стрелки с hit area 48 |
| Заголовок секции | 24/30 bold, отступ сверху 24, снизу 12 |
| Сводка | padding 20, radius 20, обводка 1.5–2; кольцо 132, stroke 8, дуга около 270° |
| Остаток | 28–32 bold; подпись 14/20; рядом «Съедено», под кольцом явная дневная цель |
| Полосы БЖУ | три равные колонки, gap 16, высота полосы 6, скругление 3; порядок как в референсе: углеводы, белки, жиры |
| Прием пищи | общая карточка с dividers; строка минимум 80, значок 44, круглая кнопка + 44 внутри touch area 48 |
| Продукт дневника | отдельные вложенные строки минимум 64; контекстное меню и тап массы |
| Поиск | минимум 56, radius 16, обводка 2 при фокусе, иконка 24, текст 16 |
| Фильтры | высота минимум 44, две колонки либо wrap при крупном шрифте |
| Результат поиска | минимум 64, title 16/22, subtitle 13/18, ккал 16; + 28 внутри hit area 48 |
| Панель выбора | минимум 72 + bottom safe area, счетчик 48, кнопка Готово минимум 52; список получает нижний padding |
| Строка цели | минимум 64, multiline минимум 80, padding 16, chevron 20; подпись и значение flex без переполнения |

На 360 px и при крупном шрифте кольцо располагается над числовой сводкой, БЖУ допускают перенос, кнопки остаются доступными. В светлой теме сохраняется та же композиция. Голден-тесты проверяют обе темы и несколько масштабов текста; финальная оценка проводится на Android, а не только по статическому макету.

## Дизайн-система

- Material 3; размеры в logical pixels. Основная сетка 4, горизонтальные поля 16, промежутки карточек 12, padding карточки 16, radius 20. Touch targets минимум 48×48. Нижние элементы учитывают safe area.
- Темная тема: фон `#111719`, поверхности `#1D2528`, повышенные поверхности `#273236`, текст `#F3F7F7`, вторичный `#B3C2C5`, акцент `#56DCC6`, ошибка `#FFB4AB`. Светлая: фон `#F5F8F8`, поверхность `#FFFFFF`, текст `#172225`, вторичный `#526469`, акцент `#006B5D`, ошибка `#BA1A1A`. Контраст проверяется перед утверждением.
- Roboto с поддержкой кириллицы: заголовок 28/34 semibold, экранный 24/30, карточки 18/24, основной текст 16/24, подписи 13/18, ключевой счетчик 32/38. Не обрезаем содержимое при системном масштабировании шрифта.
- Белки/жиры/углеводы имеют отдельные цвета и текстовые подписи; информация никогда не кодируется только цветом. Screen reader получает название, значение и действие.
- Анимации 160–240 мс, кольцо 300 мс, учитывается reduce motion. Ошибка не исчезает без прочтения; сохранение подтверждается состоянием данных.

## Карта экранов

Вход → дневник. Нижняя навигация: Дневник / Продукты / Цели / Настройки. Вес и его история доступны из Целей. Общая история синхронизации и конфликты — из индикатора статуса и Настроек.

Дневник → календарь; выбор приема → Добавление еды → Детали/порция → очередь выбранного → Готово → дневник. Каталог → карточка → Редактирование / Порции / История → Просмотр версии → Восстановление. Настройки → Backup → Preview импорта → Подтверждение объединения.

## Дневник

- Верхняя строка: дата/«Сегодня», кнопка календаря, стрелки по дням. Календарь явно выделяет текущий и выбранный дни.
- Сводка: кольцо около 132×132, потреблено/остаток/цель; превышение подписывается «Сверх цели», а не отрицательным «остатком». Рядом или ниже — три полосы БЖУ, граммы и цели. На узком экране элементы переносятся.
- Единая карточка четырех приемов с разделителями, как в референсе: заголовок, ккал, кнопка +, раскрываемые строки продукта (название, масса/порция, ккал). NULL-БЖУ обозначаются как неизвестные; нулевые значения показываются только если известны.
- Тап строки открывает количество с live preview. Меню: изменить, повторить, копировать, удалить. Меню приема: копировать с выбранной даты; preview показывает источник, состав и итог.
- Удаление и изменение дают snackbar «Отменить». Отмена после отправки на сервер — новая компенсирующая операция, с защитой версий; конфликт объясняется пользователю.
- Пустой день показывает реальные пустые приемы и действия добавления, без демо-еды или вымышленной активности.

## Добавление еды и порции

- Верх: прием пищи/дата, поиск с debounce около 250 мс, переключатели Все / Частые / Недавние / Избранное, действия Создать продукт и Быстрые КБЖУ.
- Строка: название, бренд, базовые КБЖУ/единица, избранное и +. Тап открывает детали. + использует последнюю валидную порцию; если ее нет/она удалена — открывает выбор.
- Детали: базовая ценность, selector единицы, десятичное количество (точка и запятая), рассчитанная масса/объем и итоговые КБЖУ. г и мл нельзя переключать без известной конвертации.
- Нижняя закрепленная панель: количество выбранных, итог ккал, «Готово». Выбранные записи можно пересмотреть/удалить; сохранение всех записей атомарное. Выход с несохраненным выбором требует решения.
- Быстрые КБЖУ: обязательные калории, необязательные БЖУ/название. Пустые БЖУ остаются неизвестными. Ошибки ввода объясняются рядом с полем.
- Создание/редактирование: имя, бренд, 100 г/100 мл, КБЖУ, список порций. Похожие продукты показываются до сохранения, с возможностью открыть существующий.

## Каталог, история и конфликты

Поиск по имени/бренду; релевантность учитывает точное/начальное совпадение и личную частоту. Скрытые продукты исключены по умолчанию, доступны через фильтр. История показывает автора, время и измененные поля. Восстановление версии показывает preview изменений и создает новую версию.

Конфликт: три состояния «до изменения», «ваше изменение», «на сервере», выбор по полям и явное сохранение новой версии. Порции сравниваются как часть продукта. Не предлагается молчаливое перезаписывание.

## Мои цели и вес

- Карточки: тип цели; исходный/текущий/желаемый вес; изменение в неделю; суточные калории; БЖУ; активность с коэффициентом; формула и ее входные данные; автоматический/ручной режим.
- Расчет поясняет BMR → множитель → TDEE → поправка → итог и ограничения. Поля формулы появляются по необходимости, процент жира обязателен для Кэтча—Макардла.
- БЖУ: шаблон/авто/ручной, проценты или граммы, preview и проверка суммы. Калорийность продуктов не пересчитывается из БЖУ.
- Сохранение показывает дату вступления цели в силу. История доступна отдельно; прошлые дни сохраняют прежние нормы.
- Вес: ввод даты и значения, список измерений и доступный график; редактирование/удаление/отмена. Нет искусственно созданных измерений.

## Авторизация, настройки и состояния

Email/пароль, toggle видимости, восстановление доступа, понятные ошибки, отсутствие публичной регистрации в режиме приглашений. Возврат по recovery deep link проверяется на Android.

Настройки: тема темная/светлая/системная (первая установка — темная), аккаунт/выход, синхронизация и конфликты, экспорт/импорт, сведения о приложении. При выходе с очередью объясняется, что записи сохранены локально и отправятся после входа в этот же аккаунт.

Каждый экран имеет loading/empty/error состояния с работающим повтором. Офлайн не блокирует локальные операции; синхронизация показывает число ожидающих, последнее успешное время, ошибки и ручной повтор. Потеря авторизации не удаляет записи. Skeleton применяется только до первого локального чтения.
