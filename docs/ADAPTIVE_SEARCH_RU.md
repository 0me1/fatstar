# Адаптивный поиск и тактильный отклик — 1.1.0

## Что изменилось

Раньше каталог фильтровался по вхождению одной строки в название/бренд в UI,
затем сортировался по общей частоте. Теперь запрос разбирается на слова,
кандидаты извлекаются из локального индекса SQLite, а текстовая релевантность
и личные предпочтения рассчитываются вне UI в Dart isolate.
Авторизация, изоляция файлов БД аккаунтов, Riverpod, порции, снимки КБЖУ,
история версий и очередь синхронизации используются существующие.

Поиск работает без интернета по загруженной части каталога. Нет облачного ИИ,
платных API и отправки новой статистики на сервер. Предпочтения выводятся из
активных личных записей дневника и избранного; просмотр карточки ничего не
прибавляет. Изменение или удаление записи инвалидирует локальный кеш.

## Ранжирование

Строгий порядок текстовых групп: точное название → все слова → префиксы слов
→ альтернативные названия → подстроки → исправленная раскладка → опечатки.
Раскладка и нечеткий поиск применяются, если обычный запрос не дал результатов.
Все слова запроса обязательны; числовые токены сопоставляются точно.
При отсутствии результатов обе стратегии сочетаются: `uhtrxrf` → «Гречка».
Для опечаток используется ограниченная выборка по индексам биграмм и согласных,
затем расстояние Дамерау — Левенштейна (1 ошибка от 4 символов, 2 от 6).
Полный каталог не перебирается на UI при каждом символе.

Внутри одной текстовой группы личный балл:
`min(90, 6*ln(1+число добавлений) + 2*за7дней + 0.5*за30дней +
15/(1+давностьВднях/3) + 12*избранное + 5*числоВВыбранномПриеме)`.
Фильтр «Недавние» ставит дату первой, «Частые» — число добавлений за 30 дней,
затем за 7 дней и за всю историю.
При равенстве — исходное название и UUID. Даже максимальный личный балл
не может обойти более сильную текстовую группу. Учитывается прием пищи,
из которого открыт поиск; дневник другого пользователя не используется.

Словарь `search_lexicon.dart` различает эквиваленты и разговорные названия.
Например, «макароны» не подменяют томатную, зубную или ореховую пасту.
Это поисковые связи, а не объединение продуктов. В карточке можно задать
до 32 собственных альтернативных названий (по одному в строке).
Они сохраняются в существующем JSON продукта, синхронизируются и входят в
штатную историю версий. Новых таблиц или RLS на сервере не требуется.

## Запросы и порции

| До | Теперь |
|---|---|
| `кур груд` не находил целую строку | Находит «Куриная грудка» по префиксам |
| `малако` не находил молоко | Ограниченный нечеткий поиск |
| `vjkjrj` не находил молоко | Дополнительная стратегия раскладки |
| `греча` не находил гречку | Словарь разговорных обозначений |
| `молоко 2.5` не совпадало с `2,5` | Единая нормализация десятичных чисел |
| `рис вареный` зависел от ё/е | Находит вареный рис, без сухого |

Число без единицы не считается массой или процентом автоматически.
`творог 5% 180 г` ищет «творог 5» и явно предлагает 180 г в панели порции,
если базовая единица продукта — граммы. Продукты в мл не переводятся в г.
Пищевая ценность не выводится из поисковых догадок.

Быстрый плюс показывает фактическую последнюю допустимую порцию либо 100 г/мл.
Обычное нажатие открывает существующую панель порции. Типичная порция выводится
отдельно по единице измерения из истории; именованные порции используют прежние
коэффициенты. Сохранение происходит сразу в SQLite, затем обновляется дневник;
«Готово» закрывает экран и не добавляет записи второй раз. Подтверждение имеет
действие «Отменить», а список добавленного позволяет удалить отдельную запись.

## Схема SQLite

Миграция Drift v3 сохраняет продукты, личные данные, версии, outbox и курсор.
Поддержаны обновления v1→v3 и v2→v3. При миграции строится начальный индекс. Изменение версии словаря также
перестраивает индекс однократно; обычный запуск этого не делает.

- `food_search_documents`: нормализованные название, бренд, aliases, скрытый статус.
- `food_search_tokens`: индекс токенов/согласных, связь с UUID.
- `food_search_grams`: индекс биграмм, связь с UUID.
- `food_search_fts`: FTS5 unicode61, если сборка SQLite его поддерживает.

Без FTS5 работают индексированные токены и биграммы. Центральная запись продукта
обновляет индекс в одной транзакции при локальном сохранении, ACK, загрузке
изменений, разрешении конфликта и восстановлении. Soft delete исключает продукт
из индекса; `active=false` доступен только через «Показать неактивные».
Исторические записи дневника содержат снимки и не меняются от переиндексации.

Лимит каждой выборки кандидатов — 600, суммарно не более 1800 документов;
результаты открываются по 40 строк. Личные продукты пустого запроса добавляются
по UUID даже за пределами стартовой алфавитной выборки. Это ограничение защищает
от дорогого нечеткого сравнения огромного каталога; для очень общих запросов
уточнение названия/бренда улучшает полноту.

## Интерфейс и отклик

Пустой запрос показывает компактные блоки выбранного приема, недавних, частых
и избранного. Пустые блоки скрываются; без истории предлагается реальный каталог.
Debounce — 150 мс. Номер запроса и идентичность БД защищают от устаревших ответов.
При нажатии выдача фиксируется до завершения жеста, сохраняются запрос и скролл.
Новые строки мягко появляются за 180 мс без повторной анимации прежних результатов.
Поле получает фокус при открытии добавления; действия доступны в верхнем меню
при открытой клавиатуре. Новые цвета и темы берутся из прежней дизайн-системы.

После успешного удаления еды свайпом и через меню «три точки» вызывается
`HapticFeedback.mediumImpact`; неудачная операция не подтверждается вибрацией.
При успешном добавлении — легкий отклик. Кнопка плюса и панель порций сохраняют
существующие анимации с учетом уменьшения движения; ввод текста не вибрирует.
Android решает, воспроизводить ли системный тактильный эффект.

## Проверки и ограничения

Новые проверки находятся в `food_search_test.dart`, `search_storage_test.dart`,
`search_widget_test.dart`; существующий тест удаления дополнен проверкой обоих
путей и системных вызовов тактильного отклика. Проверяются нормализация, все
запросы ТЗ, числовые характеристики, синонимы, контекст, аккаунты, удаление,
приоритет текста, миграция, FTS/token fallback, обновления индекса и UI.

Бенчмарк создает 2000 продуктов только в тестовой БД и печатает холодную/повторную
задержку после debounce. Это измерение CI runner; фактическая задержка на вашем
телефоне и ощущение вибрации требуют проверки на устройстве.

[Финальный запуск CI](https://github.com/0me1/fatstar/actions/runs/38234231838)
успешен: анализ без замечаний, 108 Flutter-тестов, 17 серверных и 2 Android-теста.
Подписанный APK 1.1.0+9 установлен и запущен на эмуляторе; файл доступен в
артефакте `calorie-diary-signed-release`. Подробные измерения записаны в
[техническом отчете](TECHNICAL_REPORT_RU.md).

Возможное развитие: расширять проверенный словарь синонимов, хранить готовые
производные агрегаты при очень большой истории и применять постраничный поиск
для каталога с десятками тысяч одинаковых по тексту названий.
